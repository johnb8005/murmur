# Murmur

A small, members-only Twitter-like app for sharing links: passkey accounts with unique usernames, one timeline, likes, comments, Web Share, PWA with a share target. A post is called a *murmur* in the UI (`POST_NOUN`); the API and code keep `posts`. Murmurs carry tags (labels: `#hashtags` in the text plus the composer's tag field, `post_tags` table, `/t/:tag` page), may carry one picture (`posts.image_*`, bytes in R2 under `images/<id>` or the `images` table without R2, served at `/images/<id>` with the same viewer rules; `src/image.ts` shrinks it client-side; `public/share-target.js` runs in the service worker so the Android share sheet can hand a picture to `/share`) and may be private (`posts.private`: only the author sees them; every query goes through `loadPosts` / `visiblePostOwnerId` with a viewer). Everything but sign-in, sign-up and device links needs an account. Rust server (axum + orpc-rs, one static binary) + Turso + R2, shipped as a container image on GHCR (`.github/workflows/publish.yml` builds the `Dockerfile` for amd64 and arm64 on native runners and merges them into one manifest, on pushes to `main` and `v*` tags; nothing deploys from the repo, the host pulls `ghcr.io/johnb8005/murmur` and sets the env from `.env.example`). The image is distroless: the binary, `dist/` and CA certificates, no shell. Johan Boissard's identity page (the `personal-website` repo) links here.

## Commands

- `bun install` (the web app and the e2e test; Playwright's browser is not downloaded, `bunx playwright install chromium` once locally) and a stable Rust toolchain for the server
- `bun run typecheck` / `bun run build` — the app; `cargo build --release` — the server (`target/release/murmur`)
- `bun run dev` — API on :8080 (`cargo run`; use `cargo watch -x run` for reloads) plus Vite on :5173 proxying `/rpc`, `/api`, feeds and previews. Needs a `.env` (see `.env.example`, loaded by the server too); `SITE_URL=http://localhost:5173` there, it is the WebAuthn origin
- `bun run start` — serve the built app with the API on `$PORT` (`murmur` with no arguments; `murmur health` probes `/api/health`, `murmur export-types <path>` writes the client types)
- `cargo test --release` (`bun test`) — unit tests: links and tags, WebAuthn verification, meta-tag parsing, and that `src/bindings.ts` matches the router (regenerate with `bun run types` when the API changes; also run by `test.yml`)
- `bun test/e2e.ts` — after `bun run build && cargo build --release`: sign-up, posting, pictures, private murmurs, device link and feed token flows in Chromium with a virtual authenticator (also run by `test.yml`)

## Layout

- `server/main.rs` — the binary: `.env`, migrations, pruning, `axum::serve` with graceful shutdown; `server/app.rs` what every request reaches (database, R2, HTTP client, site config, build info)
- `server/http.rs` — everything that is not the API: built app, `/feed.xml`, `/feed.json`, `/previews/<hash>.jpg` and `/images/<post id>` (session cookie or `?token=<feed token>`, else 401; pictures also need the post to be visible), `POST /share` (no-service-worker fallback: redirect to the composer), oRPC mounted at `/rpc` (protocol) and `/api` (OpenAPI style) through `orpc-axum`, and the `res_headers` layer that carries a procedure's set-cookie onto the response. Every page gets the same generic Open Graph card (the `<!-- og -->` placeholder in `index.html`, image `public/og.jpg` from `scripts/og-card.ts`; a `/p/:id` URL only says a murmur was shared): post content must not unfurl, and `sharePost` shares the address alone
- `server/router.rs` — the API: `auth.*`, `posts.*` (list/get/create/delete/like/comment/deleteComment/tags; `list` takes `tag`, `create` takes `tags` and `private`), `users.get`, `previews.refresh`, `health` (database round trip, 503 with a degraded body when it fails; the Dockerfile's `HEALTHCHECK` probes it). `Ctx` resolves the session cookie (or `ADMIN_TOKEN` as the owner); `authed()` requires it and is the default for everything but health, sign-in/up and `auth.link*`. `build_router()` is called once per transport. `bindings_ts()` exports the client types
- `server/auth.rs` — accounts, challenges, device links, sessions, feed tokens; `server/webauthn.rs` — WebAuthn itself, shaped like `@simplewebauthn/server` (options the browser lib consumes; verification of registrations and assertions; ES256, RS256, EdDSA; attestation requested as `none` and not checked). Passkey rows are unchanged from the TypeScript server: credential id, raw COSE key, counter, transports. Usernames `[a-z0-9_]{3,20}`, unique. Passkeys are discoverable. Challenges, device links (`kind = 'device-link'`, single use, 10 min) and sessions are Turso tables; feed tokens live on `users`. Minting a device link needs a fresh assertion with one of the account's passkeys (`kind = 'reauth'`: `auth.linkChallenge` then `auth.linkCreate`), a session cookie alone is not enough. `OWNER_USERNAME` may moderate and inherits single-admin-era posts
- `server/preview.rs` — link previews from meta tags (`scraper`), with the page's first visible text as the fallback description; no browser, so a page without an og:image gets a text card. `server/r2.rs` image bytes (`rust-s3`); `server/db.rs` libsql wrapper, schema + additive migrations
- `server/links.rs` — post model, link extraction, tag normalization, RSS/JSON Feed. `shared/links.ts` is the client's copy of the model and the tag helpers: keep `normalize_tag` / `normalizeTag` and the hashtag regex in step
- `src/bindings.ts` — generated client types (`bun run types`), checked in so the app builds without Rust; `cargo test` fails when it is stale
- `src/` — React 19 + Tailwind 4: `app.tsx` (`RequireAuth` wraps every route but `/login` and `/link/:token`), `auth.tsx` (session context, passkey flows), `ui/timeline`, `ui/compose` (text, picture, tag field, Only me switch), `ui/post` (card, labels, like, share), `ui/tags` (`/t/:tag`), `ui/postpage` (comments), `ui/profile` (own profile also has "Add another device"), `ui/login`, `ui/settings` (profile, passkeys, add another device, feed URLs), `ui/link` (`useDeviceLink` + `DeviceLinkCard`: passkey check, QR code, polls until the new device is in; and the `/link/:token` page), `ui/share` (share-target landing). `vite.config.ts` holds the PWA manifest (`share_target` → `/share`) and Workbox rules

## Conventions

- Rust for the server (edition 2024, `cargo fmt` and `cargo clippy -- -D warnings` clean), TypeScript run by Bun for the app and the e2e test; no Node-specific tooling
- oRPC for every client/server call; add procedures to `server/router.rs` with `Route` metadata, then `bun run types` so `src/api.ts` picks up the types. Input structs: `#[serde(default)]` on optional fields (exports as `field?`), `lenient_u32` / `lenient_bool` for anything that may arrive as a query string
- Keep `/api/*` paths stable, they're used from curl. Picture upload on `/api/posts` takes oRPC's multipart envelope, not plain form fields
- Additive schema changes only: new columns go in `LATER_COLUMNS` in `server/db.rs`
